# 전사문 생성 절차

meetings/의 회의 폴더에서 STT 원본·녹음·메모를 교차 대조해 전사문을 만든다.
Claude Code는 `/transcript`로 실행한다. 다른 에이전트는 이 파일을 읽고 그대로 따른다.
아래 `$ARGUMENTS`는 사용자가 덧붙인 말(예 `no-whisper`)이다.

회의 폴더 `meetings/YYYY-MM-DD_회의명/` 구조:
- `0_source/` 원본. 이 폴더의 파일은 원본이며 수정 금지.
- `1_extract/` 기계 추출 (Whisper json, `slides.md`).
- `2_transcript/` 전사문 `external.md`·`internal.md`, 에이전트 작업 기록 `transcript_log.md`(1절 확인 요청, 2절 메모 분류표, 3절 불일치·가정. 사용자는 읽지 않음).
- `3_minutes/` 종합본·메일 본문 (회의록 절차가 만든다), 공유본 (종합본에서 `scripts/make_shared.py`로 생성).

구간:
- `external` 본회의. 협업처가 있으면 협업처와 함께한 회의이며 공유본 대상. 협업처가 "없음"이어도 본회의는 external.
- `internal` 회의 후 내부 논의 (교수님 피드백·스탠드업). 내부 전용.
- 같은 구간이 둘이면 `internal_2_audio.m4a`처럼 번호를 붙인다. 이하 `<구간>`은 `external`·`internal`·`internal_2` 등을 가리킨다.

입력 (`0_source/`):
- `<구간>_audio.m4a` 녹음
- `<구간>_stt.txt` STT 서비스 export (`.md`·`.srt`도 가능). 서비스는 상관없다.
  정렬 스크립트가 `MM:SS 화자` 머리줄, `화자 MM:SS` 머리줄, `[MM:SS] 화자: 본문`, SRT 자막을 인식한다.
- 메모: 회의 중 손으로 적거나 실시간으로 타이핑한 기록. 기본 이름은 `notes.md`이지만 이름은 상관없다. 없을 수 있음.
  `0_source`의 `.md`·`.txt` 중 `<구간>_audio`·`<구간>_stt`로 시작하지 않는 파일은 모두 메모 후보다.
  이름에 note·메모가 들어가지 않은 후보는 1단계에서 메모로 읽을지 사용자에게 한 번 확인한다.
  이하 `notes.md`는 이 메모 파일(들)을 가리킨다. 여러 개면 모두 읽는다.
- 발표 자료: `slides.pptx` (실제 발표에 쓴 최종본, 커밋 제외). 없을 수 있음.
  텍스트는 `1_extract/slides.md` (커밋). 없고 pptx만 있으면 `uv run scripts/extract_slides_text.py "<회의 폴더>/0_source/slides.pptx" --out "<회의 폴더>/1_extract/slides.md"`로 만든다.
  셸 리다이렉트(`>`)는 쓰지 않는다 (Windows PowerShell 5.1은 UTF-16으로 저장).
- `experiments/`의 파일은 전사문·용어 판단의 근거로 쓰지 않는다.

절차:
1. meetings/ 아래 회의 폴더를 확인한다. 여러 개면 대상을 물어본다.
   - 회의 폴더 만들기(`_templates/YYYY-MM-DD_meeting-name/` 복사 후 이름 변경)와 `0_source/`에 원본 넣기는 사용자가 한다 (AGENTS.md Folder Convention "원본 넣기").
   - 원본을 임의로 찾지 않는다. 회의 폴더나 `0_source/`가 비었거나 필요한 파일이 없으면
     `_config/me.md`의 "녹음·STT 파일을 받아 두는 폴더"를 찾아봐도 되는지 먼저 묻는다 (비어 있으면 어디서 찾을지 묻는다).
     허락받은 경우에만 그 폴더에서 찾아 이름 규칙대로 복사한다 (원래 파일은 지우지 않음, 회의 폴더가 없으면 틀을 복사해 만듦).
   - `0_source/<구간>_*`로 구간을 파악한다. 구간마다 녹음과 STT 원본 중 하나 이상이 있어야 한다.
   - 구간 이름이 `external`·`internal`이 아니면 어느 쪽인지 물어본다.
   - 메모를 채팅으로 받으면 `0_source/notes.md`로 그대로 저장한다. 파일로 받으면 확장자를 바꾸지 않고 `0_source/`에 둔다.
     이미 있으면 덮어쓰지 말고 추가 메모를 어떻게 둘지 사용자에게 묻는다.
2. `_config/project.md`, `_glossary/terms.md`, `_glossary/speakers.md`, `notes.md`를 읽는다.
   직전 회의 전사문(직전 회의 폴더의 `2_transcript/*.md`)은
   참석자·주제·용어 파악용으로 앞부분만 훑는다. 형식이 달라도 무방하다.
   발표 자료가 있으면 `1_extract/slides.md`를 `=== pN` 단위로 15페이지씩 나눠 읽고 용어·고유명사·수치 표기를 파악한다.
   쪽수는 장표에 인쇄된 번호로 적는다. pN은 파일 순서이며 인쇄 번호와 다를 수 있다 (표지 무번호면 pN−1).
   인쇄 번호는 slides.md만으로 판정할 수 없으므로 `0_source/slides.pptx`를 확인하거나 사용자에게 묻는다.
3. Whisper 결과를 준비한다.
   - `$ARGUMENTS`에 `no-whisper`가 있으면 이 단계를 건너뛴다.
   - `1_extract/<구간>_whisper.json`이 있으면 그대로 쓴다.
   - 없으면 `command -v uv` 확인 후 `uv run scripts/transcribe_audio.py "<회의 폴더>/0_source/<구간>_audio.<확장자>"` 실행.
     출력은 `1_extract/<구간>_whisper.json` (폴더가 없으면 스크립트가 만든다).
     한 시간 녹음에 GPU로 약 10분 걸리므로 백그라운드로 실행한다.
     GPU가 없으면 스크립트가 CPU로 전환하며 몇 배 느려진다. 처음 실행하는 PC는 모델·라이브러리 내려받기(수 GB)가 먼저 일어난다.
   - 실행할 수 없으면 Whisper 없이 진행할지 물어본다.
4. 구간마다 `uv run scripts/align_stt_whisper.py --stt <0_source/<구간>_stt.<확장자>> --whisper <1_extract/<구간>_whisper.json>`으로 정렬 출력을 받는다.
   STT 결과가 `.docx`·`.pdf`면 AGENTS.md Input Conversion대로 `1_extract/<구간>_stt.md`로 변환해 그 파일을 `--stt`로 준다.
   STT 원본이 없으면 `--whisper`만 준다.
   "STT 블록을 하나도 찾지 못함"으로 멈추면(시각이 없는 등 인식 못 하는 형식) `--whisper`만으로 정렬 출력을 받고,
   STT 원본은 같은 내용 범위를 직접 읽어 `[S]` 대신 대조한다. 원본을 다른 형식으로 옮겨 적지 않는다.
   10분이 넘는 녹음은 `--start 00:00 --end 10:00`처럼 10분 단위로 나눠 읽는다
   (30분 단위는 출력이 약 60KB라 도구 출력 한도를 넘음).
5. 화자를 정한다.
   - STT `참석자 N`을 호칭·발표 순서·역할과 speakers.md로 실명에 연결한다.
   - 화자 표시가 없는 원본은 `[W]` 문장 단위로 쪼개 맥락으로 화자를 배정한다.
   - 맥락으로 판단되지 않는 배정은 문장마다 묻지 말고, 시각·후보를 transcript_log.md 1절 화자 확인 표에 모은다.
     10단계 확인 목록에 넣어 반드시 사용자에게 확인한다.
   - 단, 회의록 내용에 영향이 없는 화자(맞장구·짧은 응답 등)는 묻지 않고 추정대로 둔다.
     묻는 대상은 의견·지시·결정·수치 발화처럼 화자에 따라 공유본 포함 여부나 담당자가 바뀌는 것뿐이다.
   - 인명 표기는 speakers.md > 메모 > 녹음 순. 메모는 화면 이름 등을 보고 적은 것이라 녹음 인식보다 정확하다.
   - 화자 표기는 실명. 실명을 모르면 speakers.md의 역할 표기, 그것도 없으면 `연구원(미상)`·`{협업처 약칭}(미상)` (`_config/project.md`). 협업처가 "없음"이면 `참석자(미상)`.
6. 블록마다 `[S]`(STT)·`[W]`(Whisper)·메모를 대조해 문장을 확정한다.
   - 우선순위: 용어사전 표기 > 두 엔진 일치 > 발표 자료 > 메모 > 회의 맥락.
   - 발표 자료는 엔진끼리 갈리거나 알아듣기 어려운 용어·수치를 판정하는 근거로만 쓴다.
     발화가 자료와 다르면(발표자가 다르게 말함) 말한 그대로 두고 transcript_log.md 3절에 불일치로 적는다.
   - 메모는 `notes.md` 전체를 가리킨다.
   - 두 엔진이 다르면 일반 문장을 포함해 위 우선순위로 더 그럴듯한 쪽을 본문에 쓴다. 이것만으로는 표시하지 않는다.
   - 한쪽 엔진에만 있는 문장은 맥락에 맞으면 넣는다.
   - `[?? MM:SS]`는 다음 두 경우에만 붙이고 transcript_log.md 1절 다시 들을 구간에 두 엔진 원문을 함께 적는다.
     - 수치·고유명사·결정·담당자·기한이 두 엔진에서 다르고 메모·맥락으로도 정할 수 없을 때.
       더 그럴듯한 쪽을 본문에 쓰고 바로 뒤에 표시.
     - 두 엔진 모두 알아들을 수 없을 때. 본문에는 표시만 남김.
   - 수치·고유명사·결정·담당자·기한 표시는 지점마다 각각 붙인다 (공유본 확인 대상이 빠지지 않도록).
   - 두 엔진 모두 불명인 지점만 한 블록에서 첫 지점에 하나로 합치고, 각 지점 원문은 transcript_log.md 1절 한 행에 모은다.
   - 요약하지 않는다. "어", "음" 같은 의미 없는 군말만 지우고 "네" 같은 응답은 남긴다.
   - 없는 내용을 만들지 않는다.
   - STT 원본 안에 사람이 남긴 메모(괄호 속 의견 등)가 있으면 본문에서 빼고 transcript_log.md 3절에 옮긴다.
7. `2_transcript/<구간>.md`를 저장한다. 형식:

   ```
   # {회의명} {구간} 전사문

   00:05 홍길동
   네 제가 발표 진행하도록 하겠습니다.

   00:07 이책임
   예, 알겠습니다.
   ```
   - 화자가 바뀌는 곳마다 새 블록. 시각은 그 발화의 시작 시각.

8. 메모를 분류해 `2_transcript/transcript_log.md`를 저장한다. 메모 하나에 external·internal 내용이 섞여 있으므로
   항목마다 대응 발화가 어느 구간에 있는지 먼저 찾는다.
   - 구간은 external 먼저, internal 다음 순서로 처리한다.
   - transcript_log.md는 회의 폴더에 하나만 두고, 구간을 처리할 때마다 내용을 누적한다.
   - transcript_log.md는 에이전트 작업 기록이다. 사용자는 읽지 않는다.
     회의록 내용에 영향을 주는 확인 사항은 10단계에서 채팅으로 확인받는다.
     남은 것 중 해석의 여지가 있는 것만 회의록 절차가 종합본 해당 위치에 `[? <구간> MM:SS 사유]`로 옮긴다.
   - 전사문 안의 확인 표시는 `[?? MM:SS]`만 쓴다 (구간은 파일 이름이 나타냄).
   - 1절 확인 요청, 2절 메모 분류표, 3절 불일치·가정 순서로 둔다.
   - 메모 분류표에는 메모 전 항목을 넣는다. 아직 처리하지 않은 구간에 해당하는 항목은 분류를 "미처리"로 두고,
     그 구간을 처리할 때 다시 판정한다.
   - 한 메모가 두 구간 모두에 대응하면 대응 발화 열에 둘 다 적고,
     공유본 포함 여부는 external 구간 발화만으로 판정한다.
   형식:

   ```
   # {회의명} 전사 기록

   ## 1. 확인 요청
   ### 1.1 다시 들을 구간
   | 구간 | 시각 | 사유 | 해결 |
   |---|---|---|---|

   ### 1.2 화자 확인
   | 구간 시각 | STT 표기 | 후보 | 근거 | 해결 |
   |---|---|---|---|---|

   ## 2. 메모 분류표
   | # | 메모 항목 | 대응 발화 | 분류 | 공유본 |
   |---|---|---|---|---|
   | 1 | 시험 조건 재확인 | external 12:30 이책임 | 협업처 지적·요청 | 포함 |

   ## 3. 불일치·가정
   - …
   ```
   분류 기준:
   | 분류 | 판단 근거 | 공유본 |
   |---|---|---|
   | 협업처 지적·요청 | 협업처 참석자 발화와 대응 | 포함 |
   | 교수님 피드백 | 교수님 발화와 대응 | 제외 |
   | 내부 참석자 지적 | 연구실 인원 발화와 대응 | 제외 |
   | 자체 발견 | 대응 발화 없음 (발표자료 오류 등) | 제외 |
   | 할 일 메모 | 발표 중 옮겨 적은 할 일 | 발화로 확인된 것만 참고 |
   | 판단 불가 | 근거 부족 | 제외 |
   - `internal` 구간에 대응하는 항목은 분류와 무관하게 공유본 제외.
   - 애매하면 제외로 판정한다.
   - `_config/project.md`의 공유본이 "사용 안 함"이면 공유본 열은 비운다. 협업처가 "없음"이면 "협업처 지적·요청" 대신 "참석자 의견"으로 분류한다.

9. 회의 폴더 `README.md`의 계보 표를 갱신한다. 없으면 만든다.
   - 표 열은 단계 / 만든 주체 / 입력 / 시점. 단계는 0_source, 1_extract, 2_transcript, 3_minutes.
   - 이번 처리로 만든 단계(1_extract, 2_transcript)의 행을 채우고, 기존 행과 비고는 지우지 않는다.
   - 0_source 행이 비어 있으면 함께 채운다 (원본을 넣은 주체, 시점은 회의 날짜).
10. 전사문의 `[?? MM:SS]` 중 회의록 내용에 영향을 주는 것을 사용자에게 확인받는다. 사용자는 전사문을 직접 읽지 않는다.
   - 대상은 수치·고유명사·결정·담당자·기한 표시와 화자 확인 요청 (5단계 화자 확인 표와 합쳐 한 번에 묻는다).
   - 채팅에 번호 목록으로 보여 주고 멈춘다. 항목마다 번호, 구간·시각, 해당 문장, 두 엔진 원문 요지, 사유.
   - 사용자가 채팅으로 답한 항목은 전사문에 반영하고 표시를 지운다. transcript_log.md 1절 해당 행의 해결 열에 확정 내용과 "사용자 확인"을 적는다. 미해결은 해결 열을 비운다.
   - 답하지 않은 항목과 회의록 내용에 영향이 없는 표시는 그대로 둔다. 회의록 절차가 종합본으로 옮길 때 해석의 여지가 있는 것만 `[? 구간 시각 사유]`로 남긴다.
11. 전사문에서 새로 발견한 용어·화자가 용어사전에 없으면 목록으로 보여 주고 등록 여부를 묻는다.
12. 이어서 회의록 절차(`/minutes`)를 진행할지 제안한다.

사용 예 (Claude Code. 다른 에이전트는 "전사문 만들어 줘", "Whisper 없이 전사해 줘"):
- /transcript             → 대화형
- /transcript no-whisper  → Whisper 없이 STT 원본·메모·용어사전만 대조
